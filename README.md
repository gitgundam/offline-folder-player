# 离线资源启动器

一个小型静态网页，选择配套资源目录后直接读取本机文件，提供离线入口、摇杆、视角拖动、动作按钮及存档导入导出。

网站只包含启动器和触控依赖，运行文件约 80 KB。配套资源、引擎和用户存档均不随仓库发布；文件选择发生在本机，没有上传接口，也不将整套资源复制到浏览器缓存。

## 使用

1. 用支持 Service Worker、共享内存、WebGPU 的浏览器打开 [在线入口](https://gitgundam.github.io/offline-folder-player/)。首次准备完成后会自动刷新一次，启用运行环境。
2. 选择配套的整个资源目录，其中应有 `iphone-build.json`。目录只在当前页面存活期间有效，关闭重开后重新选择。
3. 点击“开始游戏”。启动页可设置摇杆大小、透明度、视角灵敏度及自动冲刺。
4. 退出后可在“存档与迁移”中导出或导入 JSON。存档属于固定网站地址，电脑 localhost 的存档需单独导出迁移。

手机上需先联网准备 HTTPS 入口并可添加到主屏幕，之后再尝试飞行模式下关闭重开、重新选择本机目录。页面只有从离线入口启动后才显示“离线已准备好”。浏览器或系统不支持相应运行能力时会报错；网站上线不代表手机场景与性能已验证。

## 页面自动重载时

先联网打开 [更新入口](https://gitgundam.github.io/offline-folder-player/update.html)，返回后应能看到“启动排查 → 复制排查信息”。再次启动，若 Safari 自动重载，在返回的启动页复制排查信息。

启动记录仅保存在本站的本机存储，保留最后加载阶段、百分比、版本、资源读取路径、共享内存创建边界及捕获的错误；不记录资源或存档内容，也不自动上传。缺少正常退出标记只能说明运行中断，不能据此单独判断内存或 GPU 故障。WebAssembly 内存大小记录的是虚拟内存范围，不等同于常驻内存用量。

这版增加诊断记录，未改变内存预算或宣称修复 iOS 崩溃。若需判断系统是否因内存结束网页，还需结合 iOS 对应时间的 JetsamEvent 或 WebContent 错误报告。

## 触控

左摇杆移动，右侧滑动转视角；瞄准点击切换，射击按住并可拖动瞄准。顶部手动切换徒步／驾驶，提供暂停及菜单导航。第一版提供徒步、战斗、汽车驾驶和菜单按钮。复杂飞行载具未覆盖。

## 部署与开发

这是无构建依赖的静态站点。修改文件后运行：

```sh
node --test tests/*.test.cjs
node scripts/build.mjs
```

第二条命令更新 SHA-256 缓存清单和 Service Worker 版本。推送到 `main` 后由 GitHub Pages 从根目录发布。

所有链接、Worker、缓存和虚拟资源路径均限定到当前仓库的 URL 前缀。首次加载借助同一个 Service Worker 为缓存导航响应加上 COOP/COEP，再刷新启用隔离；无需注册第二个竞争的 Service Worker。此技术思路可参考 [coi-serviceworker](https://github.com/gzuidhof/coi-serviceworker)。

资源每块最多 1 MiB、最多四路读取，读取前按配套清单校验 SHA-256，最近分块仅短暂保留在内存。缺文件或校验失败时明确报错。网站的持久缓存只包含小启动器。资源包中原有的目录、存档和通信标识符保留兼容，不代表发布了资源本体。

## 依赖

摇杆为 NippleJS 1.0.4（MIT），源码及许可证位于 `controls/`，没有 CDN 请求。其余按钮使用原生 HTML、CSS 和 Pointer Events。

## 验证边界

已有电脑资源加载和场景证据，目录路径和隔离针对 GitHub Pages 单独验证。完整多指、Safari 差异、手机场景、长期性能和存档迁移仍需逐项验收；不把网站上线等同于手机可玩性通过。
